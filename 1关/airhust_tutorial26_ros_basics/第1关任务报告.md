# 第 1 关任务报告

本文档记录第 1 关的完成过程，包括环境与编译问题的修复、`flight_node` 的补全、关键知识点和运行验证。

## 1. 任务目标

第 1 关使用简化的无人机后端，不使用真实的 PX4 / MAVROS。任务分为两个阶段：

### 阶段一：编译与启动

- `catkin_make` 能够通过；
- `roslaunch drone_bringup mission.launch` 能够启动 `flight_node`。

### 阶段二：起飞与避障

- 持续发布设定点，维持 500 ms 心跳；
- 飞机目标高度升到 `1.5 m`；
- 当飞机距离障碍物小于 `0.5 m` 时开始降落；
- 高度回到 `0 m` 后任务成功。

本关涉及的主要接口：

| 方向 | 话题 | 类型 | 作用 |
|---|---|---|---|
| 后端 → 节点 | `/drone/state` | `drone_backend/DroneState` | 获取解锁状态、模式、高度、设定点链路状态 |
| 节点 → 后端 | `/drone/setpoint` | `geometry_msgs/PoseStamped` | 发送目标点，同时作为心跳 |
| 传感器 → 节点 | `/drone/sensor/obstacle_distance` | `std_msgs/Float32` | 获取与障碍物的距离 |

## 2. 阶段一：修复编译

### 2.1 修改文件

阶段一只修改两个文件：

- `src/drone_bringup/CMakeLists.txt`
- `src/drone_bringup/package.xml`

### 2.2 `CMakeLists.txt` 的修改

修改前后的关键内容如下：

```diff
 find_package(catkin REQUIRED COMPONENTS
   roscpp
   geometry_msgs
   std_msgs
+  drone_backend
 )

 catkin_package(
-  CATKIN_DEPENDS roscpp geometry_msgs std_msgs
+  CATKIN_DEPENDS roscpp geometry_msgs std_msgs drone_backend
 )

 include_directories(${catkin_INCLUDE_DIRS})

 add_executable(example_listener src/example_listener.cpp)
 target_link_libraries(example_listener ${catkin_LIBRARIES})
+
+add_executable(flight_node src/flight_node.cpp)
+target_link_libraries(flight_node ${catkin_LIBRARIES})
```

每一处修改的原因：

| 修改 | 原因 |
|---|---|
| `find_package` 加入 `drone_backend` | `example_listener.cpp` 使用了 `drone_backend/DroneState.h`，需要该包的 CMake 配置和头文件路径 |
| `catkin_package` 加入 `drone_backend` | 声明本包对外依赖，保证依赖关系完整 |
| 增加 `flight_node` 可执行文件 | `mission.launch` 中写的是 `type="flight_node"`，不编译该 target，roslaunch 就找不到节点 |

### 2.3 `package.xml` 的修改

补充 `geometry_msgs` 和 `std_msgs` 的构建依赖与运行依赖：

```xml
<build_depend>roscpp</build_depend>
<build_depend>geometry_msgs</build_depend>
<build_depend>std_msgs</build_depend>
<build_depend>drone_backend</build_depend>

<exec_depend>roscpp</exec_depend>
<exec_depend>geometry_msgs</exec_depend>
<exec_depend>std_msgs</exec_depend>
<exec_depend>drone_backend</exec_depend>
```

注意点：

- `build_depend` 表示编译时需要该包；
- `exec_depend` 表示运行时需要该包，对应旧格式中的 `run_depend`；
- `catkin_package(CATKIN_DEPENDS ...)` 中声明的每个包，都必须在 `package.xml` 中同时具备构建依赖和运行依赖，否则 `catkin_make` 会报错。

### 2.4 编译命令

`drone_backend` 是预编译在 `install/` 中的，因此编译前需要先 source 它：

```zsh

source /opt/ros/noetic/setup.zsh

```


能够看到 `flight_node` 启动，阶段一完成。

## 3. 阶段二：补全飞行逻辑

阶段二只修改：

- `src/drone_bringup/src/flight_node.cpp`

### 3.1 修改清单

| 位置 | 修改前 | 修改后 | 原因 |
|---|---|---|---|
| 循环频率 | `ros::Rate rate(1.0);` | `ros::Rate rate(10.0);` | 心跳要求 500 ms 内至少一次，1 Hz 太慢 |
| 障碍话题 | `nh.subscribe("/drone", ...)` | `nh.subscribe("/drone/sensor/obstacle_distance", ...)` | 原话题名不存在，拿不到障碍距离 |
| 目标高度 | `setpoint.pose.position.z = 0.0;` | `setpoint.pose.position.z = 1.5;` | 目标是飞到 1.5 m |
| 降落条件 | `if (distance < 0.0)` | `if (distance < 0.5)` | 距离小于 0.5 m 时降落 |
| 时间戳 | `setpoint.header.stamp = ros::Time();` | `setpoint.header.stamp = ros::Time::now();` | 默认构造的时间戳为 0，后端会丢弃该设定点 |
| 发布对象 | `g_setpoint_pub.publish(fakepoint);` | `g_setpoint_pub.publish(setpoint);` | `fakepoint` 是空消息，发的不是目标点 |

`setpoint.header.frame_id = "map";` 原本就是正确的。后端的设定点需要非空 `frame_id` 和非零 `stamp`。

### 3.2 最终的 `flight_node.cpp`

见[flight_node.cpp](./src/drone_bringup/src/flight_node.cpp)。

### 3.3 控制流程说明

程序启动后：

1. 创建 `/drone/setpoint` 发布者和障碍距离订阅者；
2. 设置目标点 `(0, 0, 1.5)`，`frame_id` 为 `map`；
3. 以 10 Hz 持续发布目标点，保证设定点链路有效；
4. 回调函数不断更新全局变量 `distance`；
5. 当 `distance < 0.5` 时，把目标高度改为 `0`；
6. 后端收到高度为 0 的目标后进入 `LAND` 模式，飞机下降；
7. 高度回到 0 附近后，后端判定成功并退出。

## 5. 学到的知识

### 5.1 catkin 工作空间

- `src/`：存放功能包源码；
- `build/`：CMake 编译中间文件；
- `devel/`：开发空间，`catkin_make` 默认生成的可执行文件和 setup 脚本；
- `install/`：安装空间，本关中的 `drone_backend` 已经预编译在这里。

编译前 source `install/setup.zsh`，是为了让 CMake 能找到预编译的 `drone_backend`；编译后 source `devel/setup.zsh`，是为了让 rosrun / roslaunch 找到自己编译出的节点。

### 5.2 `CMakeLists.txt` 与 `package.xml` 的分工

- `package.xml` 描述包的元信息和依赖关系；
- `CMakeLists.txt` 描述如何查找依赖、如何编译目标、如何链接库；
- `find_package` 负责找到依赖包；
- `catkin_package` 声明本包对外提供的依赖信息；
- `add_executable` 定义要生成的可执行文件；
- `target_link_libraries` 把可执行文件和依赖库链接起来。

### 5.3 ROS 通信

- 发布者使用 `advertise<消息类型>(话题名, 队列长度)`；
- 订阅者使用 `subscribe(话题名, 队列长度, 回调函数)`；
- 回调函数负责更新数据；
- `ros::spinOnce()` 处理一次回调队列；
- `ros::Rate` 控制循环频率；
- `PoseStamped` 包含 `header` 和 `pose`，其中 `header.stamp` 是时间戳，`header.frame_id` 是坐标系；
- 设定点既要发布正确的位置，也要满足后端的心跳要求。

### 5.4 调试思路

遇到问题时，按照“编译错误 → 运行错误 → 行为错误”的顺序排查：

1. 先看 `catkin_make` 的第一条错误，从依赖和 CMake 配置入手；
2. 再看 roslaunch 是否能找到节点；
3. 最后看话题名、消息内容、时间戳、发布频率和控制条件是否正确。
